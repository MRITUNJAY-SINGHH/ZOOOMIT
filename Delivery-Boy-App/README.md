# ZOOOMIT Delivery Partner App

The official, professional **ZOOOMIT Delivery Partner Mobile Application** built exclusively for couriers, riders, and delivery personnel.

---

## 🛵 Architecture & Features

### 1. Brand Identity & Design System
* **Brand Direction**: High-visibility yellow-and-white ZOOOMIT identity optimized for outdoor sunlight readability.
* **Colors**: Centralized tokens in `src/constants/theme/colors.js` exactly matching the customer app (`#FFC928` primary, `#111827` secondary).
* **Typography**: Gilroy font family (`Gilroy-Light.ttf`, `Gilroy-Regular.ttf`, `Gilroy-Medium.ttf`, `Gilroy-Bold.ttf`, `Gilroy-Heavy.ttf`) bundled in `assets/fonts/` and registered with Expo Font.
* **Strict Zero Shadows Rule**: **Zero shadows** across all components (no `shadowColor`, `shadowOpacity`, `elevation`, `boxShadow`). Visual hierarchy is achieved purely via clean borders, high-contrast surfaces, and crisp typography.

### 2. Authentication & Security
* **Role Enforced**: Only accounts with `role: "DeliveryBoy"` or `"Admin"` can log in.
* **Session Storage**: Access tokens securely stored using `expo-secure-store`.
* **Zero Public Signup**: Partner credentials are created by hub dispatch administrators.

### 3. Real-Time Availability & Atomic Order Acceptance
* **Online/Offline Switch**: Live availability toggle synced directly with `/api/delivery/toggle-online`.
* **Single-Partner Atomic Claim (Rule 11)**: Backend enforces atomic conditional database queries (`findOneAndUpdate`). If two riders attempt to accept the same order simultaneously, only one succeeds; the second receives an HTTP `409 Conflict` and the stale offer is dismissed with clear feedback.

### 4. Background Push Notifications (Rule 9)
* **Background & Killed State Alerts**: Device push token registered via `expo-notifications` and synced with `/api/delivery/push-token`.
* **Android Channel**: Dedicated `orders` notification channel configured with `MAX` importance, sound, and vibration pattern.
* **Deep Link Routing**: Tapping a notification while the app is closed or backgrounded automatically routes the partner to `/order/[id]`.

### 5. Delivery Lifecycle & 4-Digit OTP Verification (Rule 16)
* **Transitions**: `Assigned` ➔ `Accepted` ➔ `Arrived at Store` ➔ `Picked Up` ➔ `Out for Delivery` ➔ `Delivered`.
* **Store Checklist**: Interactive item checklist for riders to verify goods before leaving the store.
* **Server-Authoritative OTP**: The 4-digit OTP is generated by the server and visible only to the customer. When the rider enters the OTP, it is validated via bcrypt against the hashed database value. Supports maximum 5 retry limits and expiry lockout.

### 6. Free GPS Turn-by-Turn Navigation (Rule 14)
* Zero paid Google Maps SDK keys required.
* Automatically resolves pickup and customer delivery coordinates and launches native Google Maps or Apple Maps directions.

## 🚀 Getting Started

### 1. Install Dependencies
```bash
cd Delivery-Boy-App
npm install --legacy-peer-deps
```

### 2. Configure Environment
Check `.env`:
```env
EXPO_PUBLIC_API_URL=http://localhost:5000/api
```
*(When testing on physical device over Wi-Fi, the app automatically detects the local Metro IP address)*.

### 3. Launch App
```bash
npx expo start
```
* Press `a` for Android Emulator
* Press `i` for iOS Simulator
* Press `w` for Web Preview
* Scan QR code in Expo Go or development build on physical phone

```text
Delivery-Boy-App/
├── assets/
│   ├── fonts/               # Bundled Gilroy TrueType fonts

├── src/
│   ├── app/

│   │   ├── login.jsx        # Courier sign-in screen

│   │   │   ├── index.jsx    # Live Dashboard & new order offers
│   │   │   ├── orders.jsx   # Filtered orders list (New, Active, Completed, Cancelled)
│   │   │   ├── earnings.jsx # Shift payouts & incentive analytics
│   │   │   └── profile.jsx  # Vehicle info, KYC, bank details & settings
│   │   └── order/

│   ├── context/             # AuthContext (SecureStore token & partner session)
│   └── services/            # API client, push notifications, free GPS navigation, haptics
├── app.json
├── metro.config.js
```
